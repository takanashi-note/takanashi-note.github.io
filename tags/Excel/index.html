slackのBOT投稿をExcelに収集する

こんにちは、たかなしです。

今回は他チームからの相談をもとに対応した自動化を書きます。

1．課題

会社のslackに、顧客から寄せられたレビューを通知させるチャンネルがありました。

私が依頼された内容は「そこに通知される顧客からの声を、分析用にExcelに収集したい。なるべくリアルタイムで確認したいので、自動転記される仕組みを作ってほしい」といった内容でした。

当該チャンネルを見たところ、おそらくIFTTTのようなツールを使って、サービス名などのキーワードでピックアップした某SNSの投稿を、BOTがslackで通知しているようでした。

それなら、そのIFTTTを設定した社員に「slackに通知したあと、ついでにこのExcelファイルに転記するようにしてください〜」とひとこと相談すれば解決しそうだよなぁ…と思いつつ、面白そうだったのでslackの投稿をトリガーとした自動化に挑戦しました！

（担当者さんが多忙そうだったのも理由のひとつです）

今回のゴールは、「slackに投稿された内容を、OneDriveのExcelへ転記する自動化を完成させる」です。

※この記事を書くにおいて、Bot投稿があるSlackの環境を用意できず検証ができなかったため、Slackの投稿はいったん通常ユーザーの投稿を対象とします。

2．課題が発生した背景

顧客の声をざっくりサマライズして、上長報告する必要が生じたようです。

Excelファイル上で、どのカテゴリに関するご意見か？ポジティブかネガティブか？などを集計するために、レビューが届いた時点でExcelに自動転記されるような仕組みを構築したい、という依頼でした。

先に！「4．結果、どうだった？」

手順が長くなるので、先に結果を。

Slack APIとPower Automateを使って、自動転記を実現することができました。

設定手順をまとめて共有したところ、依頼者本人も同様の自動化を設定できるようになり、他の業務でも活用していると教えてもらいました。

横展開して使ってくれているのは、とても嬉しいですね。

それでは、実際に構築した手順を書き留めておきたいと思います。

3．解決するために行ったこと（構築手順）

はじめに

・本記事の内容は、2026年5月時点で動くことを検証できています。ただ、ご覧のタイミングやご利用の環境によっては、同じ方法が使えない場合があります。あなたの環境で動くことを、私が保証することはできません。

レガシーな方法が新しい仕組みのヒントになることもあるので、あくまで自分の備忘録として掲載させていただいています。

・ツールは（Slack以外は）Microsoftのものしか使えない全社方針だった、という前提があります。

・以下、「使うもの」がすべてそろっていないと構築できない手順です。

・検証しながら記事を書いていますが、間違った内容が含まれていたらごめんなさい🙇

使うもの

・Excel（Excel for Web (Excel Online) を利用します）

・Slack API

・Power Automate クラウド版（有償版でしか使えないプレミアムコネクタを利用します）

・OneDrive（またはSharepoint。この記事ではOneDriveを利用します）

(1) Excelの準備

まず、Slackの投稿内容を転記するExcelファイルを準備します。

収集したい情報のカラムをセットしたテーブルを準備してください。

分かりやすいファイル名・テーブル名をつけましょう。

準備したら、Sharepoint、またはOneDriveの任意のフォルダに格納しておきます。

組織だとSharepointを推奨します。今回は個人環境なので、OneDriveに配置しました。

Excelに転記用シートを作成、ヘッダを入力してテーブル化します。

(2) Power Automateでフローを作成する

自動化したクラウドフローを作成します。

フロー名だけ適当に入力して、トリガーは選ばず「スキップ」します。

次のページでトリガーを選びます。

「HTTP要求の受信時」というトリガーを追加

プレミアムコネクタを使います。

「フローをトリガーできるユーザー」には「誰でも（Anyone）」を選びます。

JSONスキーマは以下をコピーペーストして入力します。

「＋」からアクションを追加します。

「コントロール」から「条件」を選択します。

「条件」コネクタのパラメーターを設定します。

画像の箇所に、fx（式）を選択して「triggerBody()?[‘type’]」と入力します。

入力できたら「追加」

右側には「url_verification」と直接入力します。

以下のような状態になればOKです。

さらに、「条件」コネクタの「True」側に「応答」アクションを追加します。

Bodyにfx(式)を選んで triggerBody()?[‘challenge’] と入力し、追加します。

Falseの方にも「応答」アクションを追加します。

Status Codeに「200」、Bodyに「OK」と直接入力します。

さらに、False側に「JSONの解析」アクションを追加します。

Contentは「本文」を選択した状態で、Schemaは以下をコピペしてください。

フローを保存します。

フローを保存すると、一番上部の「HTTP要求の受信時」（ “manual” という名称に変わっているかも）の中に「HTTP URL」が作成されています。

このURLをコピーしてください。

(5) JSONスキーマの修正

あとで直す、と言っていた部分を修正します。

チャンネルに投稿されるのを待って、投稿されたらPower Automateの実行履歴を確認しましょう。

条件 >> False >> JSONの解析 >> 入力の「未加工の入力を表示する」をクリックします。

表示された内容を全コピーします。

フローの編集画面を開き、「JSONの解析」の「サンプルのペイロードを使用してスキーマを生成する」をクリックし、先ほどコピーした内容をペーストして保存すると、適したスキーマが自動生成されます。

「表に行を追加」アクションの詳細パラメータも調整して、転記したい情報が取得できるようにします。

JSONの解析の入力、出力とにらめっこして、どこに自分の転記したい情報があるかを確認します。

例えば、以下「TEST ACCOUNT」という名前の通常ユーザーの投稿内容「test 4」を転記しようとした場合、

TEST ACCOUNTさんが対象チャンネルに普通に投稿した内容が「test 4」

これを収集対象とする

転記対処となる投稿内容は、この”content” > “event” > “text” に入っている「test 4」です。

実行履歴からJSONの解析を確認すると、「test 4」はこの階層に入っていることが分かる

フローの編集画面を開き、「表に行を追加」アクション >> 詳細パラメーターの「test 4」を転記したい欄に「 body(‘JSONの解析’)?[‘event’]?[‘text’] 」とfx(式) で入力します。

編集画面を開き、「表に行を追加」アクション >> 詳細パラメーターの「test 4」を転記したい欄で

fx(式)を選び、「 body(‘JSONの解析’)?[‘event’]?[‘text’] 」と 直接入力する

入力ができたら、フローを保存して、該当チャンネルにあらためてテスト投稿してみましょう。

うまく設定できれば、Excelの該当欄に収集したい内容が転記されているはずです。

ちゃんと投稿内容が転記されました。

※他のカラムは設定を直していないので空欄のままです…

転記したい対象がBotの投稿なのか、どんなBotなのか、ユーザーの投稿なのかなどでも、JSONの構成が変わるようです。

私はJSONの理解が浅いので、ここの設定は毎回試行錯誤です…。

一応、以上で今回やりたかった設定の説明は完了です。

補足：転記対象のユーザーを指定したい場合

「このチャンネルの、このBotの投稿内容だけを収集したい！」という場合は、条件コネクタを使って「投稿者のユーザーIDがこれだったら」のような条件分岐をすればうまくいくと思います。

需要がありそうなら別の記事で書きたいです。

補足：JSON解析がうまくいかない場合

JSONの解析でエラーが発生することがあります。おそらくPower Automateの実行履歴で「失敗」として残っていると思います。

その場合、対象の実行履歴のエラーメッセージを確認して、改善していく必要があります。

詳しくは別の記事で書けたらと思いますが、ざっくり箇条書きしておきます。

・「●●の項目に指定されているデータ型は数値だけど、受け取ったのは文字列だったよ」なエラー内容だった場合

→●●で入力されうるデータ型を追加します。

・「必須で渡される予定だったデータが渡されない」のようなエラーの場合

→JSONの解析のスキーマ内で、「required」に指定している内容を削除します。

・実行履歴は成功しているが、（内容はあるはずなのに）指定した内容が転記されていない場合

→正しく指定できていないので、あらためて確認する必要があります。

環境を整える（使用ツール紹介）

これまで行ってきた自動化のナレッジを記事にするために、まずPCを前職の環境に近づけたいと思います。

使用ツール

主に使っていたツールは以下の通りです。
・Slack
・Redash
・Microsoft 365（Excel Online、Sharepoint、Power Automate、Outlook）
・BOX

自動化観点でいうと他にも使いたいツールはたくさんありましたが、セキュリティ上の懸念があったのでしょうか、利用を禁止されているものも多くありました。

1．Slack

社内のメインチャットツールです。
「全部Slackに情報を集約したい」という声が多く、「〇〇をSlackに通知する」のような自動化を多く対応しました。

2．Redash

「ダッシュボード作成ツール」と紹介されている場合も多いようですが、個人的には分析のためのデータ抽出や、Refresh Schedule機能を活用した検知業務での利用が多かったです。（ダッシュボードは別のBIツールで作って展開していました。ここでは割愛させてください）

3．Microsoft 365, BOX

データはすべてクラウドに置いていました。
Excelに蓄積させたデータを可視化するためには、使っていたBIツールの都合上、接続するExcelはBOXに格納しておく必要がありました。

データの蓄積はぜひ自動でやってほしいものですが、BOXのExcelへ直接自動化フローで書き込ませる術が見つからなかったため、私は以下のような手順を踏んでいました。
① Sharepointドキュメントライブラリに、自動転記先のExcelファイルを置いておく（データ転記の自動化はこちらで組む）② ①のExcelが更新されたら、BOXに置いておいた方のExcelファイルを①の内容で上書きする（上書きはPower AutomateのBOXコネクタを利用）

今後の記事について

以上のツールを利用した自動化フローをまとめてみます。
（環境構築するといいましたが、まだRedashとBOXがセットアップできておりません…そのうち！）
